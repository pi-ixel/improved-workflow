# US Design Writer

基于需求材料输出可开发落地的详细设计文档，经用户审批确认后，进一步拆分为可独立验收的任务分解文件。严格遵循 skill 内置模板。

## Workflow

### Phase 1: 设计文档生成

1. 定位模板文件（固定来源）。
- 默认模板路径：`<skill-dir>/references/us设计.md`。
- 除非用户明确指定其他模板路径，否则不得改用项目根目录模板。
- 若内置模板缺失，明确报错并要求先补齐该文件。

2. 收集输入材料。
- 读取用户需求、历史设计文档、接口约束、代码现状、测试基线。
- 提取明确事实：目标、范围、受影响模块、接口、数据、测试口径、非功能指标。

3. 按模板逐段填充内容。
- 保持模板一级/二级标题不变。
- `WHY` 仅写背景与现状，不写方案细节。
- `文档` 使用目录树代码块列出参考资料。
- `核心机制` 必须包含 mermaid 图。
- `实现细节` 必须包含接口原型、返回值、错误码、非功能约束。
- `验证和测试` 覆盖正常、异常、边界、性能、回归、可观测性。
- `任务分解` 按里程碑输出，包含 DoD 与交付物。

4. 处理不确定信息。
- 禁止猜测。
- 无法确认的信息标记 `【存疑】`。
- 在对应段落追加 `待确认问题：...`。
- 在文末 `存疑汇总（Open Questions）` 表中登记每个存疑项。

5. 输出设计文档。
- 默认输出到当前工作目录：`./<变更描述>-us设计.md`。
- 若用户明确要求仅在对话展示，则不写文件，仅输出 Markdown 正文。

### 审批节点

6. 设计文档生成后，询问用户：
   - **确认** → 进入 Phase 2。
   - **需要修改** → 用户提出修改意见，修改后重新询问确认（支持多轮）。
   - **中止** → 流程结束，不进入 Phase 2。

7. 多轮修改时：
- 根据用户意见修改设计文档并重新写入。
- 每轮修改完成后重新询问确认。
- 仅在用户明确确认后才进入 Phase 2。

### Phase 2: 任务分解

8. 定位任务分解模板（固定来源）。
- 默认模板路径：`<skill-dir>/references/任务分解.md`。
- 若内置模板缺失，明确报错并要求先补齐该文件。

9. 读取确认后的设计文档。
- 读取 Phase 1 输出的最终版设计文档。
- 综合考量实现方案、变更范围和验证场景，判断最优任务拆分方式。

10. 按任务分解模板填充内容。
- 每个任务为里程碑级，包含编号（T1, T2, ...）、描述、依赖关系。
- 每个任务包含 DoD checklist（功能/测试/文档三类）和交付物。
- 顺序通过编号表达，依赖通过 `依赖: T1, T2` 字段声明。
- 可并行的任务不标注相互依赖。

11. 处理不确定信息（同 Phase 1 规则）。
- 禁止猜测，标记 `【存疑】`，在文末汇总表中登记。

12. 输出任务分解文件。
- 默认输出到当前工作目录：`./<变更描述>-任务分解.md`。
- 文件头部标注来源设计文档路径，便于追溯。

## Quality Gates

生成结果前，逐项自检：

**Phase 1 自检（设计文档）：**
- 模板全部一级章节均已填写。
- `实现方案/核心机制` 含至少 1 个 mermaid 图。
- 所有接口均有原型与返回值语义。
- 至少包含 1 个异常场景和 1 个性能指标（如适用）。
- 所有 `【存疑】` 均在文末汇总表中有对应记录。
- 任务分解中的每个任务都包含 DoD 和交付物。

**Phase 2 自检（任务分解）：**
- 每个任务包含编号（T1, T2, ...）和标题。
- 每个任务包含 DoD checklist（功能/测试/文档三类）。
- 每个任务包含交付物列表。
- 依赖关系已明确声明，串行/并行关系清晰。
- 所有 `【存疑】` 均在文末汇总表中有对应记录。

## Output Rules

- 输出使用 Markdown。
- 除非用户要求，不改写模板标题文案。
- 使用简洁、工程化语言，避免空话。
- 优先给出可落地信息：接口、数据、边界、回滚、验收证据。
- Phase 2 输出文件头部必须包含来源设计文档路径。

## Template Contract

- 两阶段分别遵循对应模板约束：
  - Phase 1：`references/us设计.md`
  - Phase 2：`references/任务分解.md`
- `重要：在写作过程中出现存疑，或者无法通过上下文进行决定，不能做出任何猜测，需要标记为存疑，并抛出问题`
- 若模板与用户额外要求冲突，以用户明确要求为准，并在文档中标注偏差点。
