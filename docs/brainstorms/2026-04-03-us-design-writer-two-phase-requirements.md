# US Design Writer 两阶段流程增强

## Problem Frame

当前 `us-design-writer` skill 是一个单阶段流程：生成设计文档后即结束。用户需要手动从设计文档中提取任务并安排执行顺序。将任务拆分内建到 skill 中，可以确保设计文档和任务分解的一致性，并保证每个任务具备独立的验收标准。

## Requirements

**两阶段流程**

- R1. Skill 流程从单阶段扩展为两阶段：第一阶段生成 US 设计文档，第二阶段基于确认后的设计文档生成任务分解文件
- R2. 两阶段之间设有用户审批节点，用户可以要求修改设计文档（支持多轮），确认无误后进入第二阶段

**第一阶段：设计文档生成（保持现有行为）**

- R3. 第一阶段的行为与当前 skill 一致，读取 `references/us设计.md` 模板生成设计文档，写入 `./<变更描述>-us设计.md`

**审批节点**

- R4. 设计文档生成后，skill 询问用户是否确认，用户可以：确认进入下一步、要求修改设计文档、或中止流程
- R5. 修改可以多轮进行，每轮修改后重新询问确认

**第二阶段：任务分解**

- R6. 任务分解基于确认后的设计文档，综合考量实现方案、变更范围和验证场景，由 skill 判断最优拆分方式
- R7. 任务分解使用独立的模板文件 `references/任务分解.md`
- R8. 任务分解输出为独立文件 `./<变更描述>-任务分解.md`，与设计文档平级存放
- R9. 任务分解文件头部标注来源设计文档路径，便于追溯

**任务粒度与验收**

- R10. 每个任务为里程碑级，包含功能 + 测试 + 文档的 checklist 式 DoD
- R11. 任务有明确的顺序标识和依赖关系，表达哪些任务必须串行、哪些可以并行（不需要可视化图表）

## Success Criteria

- 用户调用 skill 后，先得到一份设计文档，经过确认/修改后，再得到一份可独立验收的任务分解文件
- 任务分解文件中的每个任务都可以被独立验收，有明确的 DoD checklist
- 任务顺序清晰，依赖关系明确

## Scope Boundaries

- 不改动现有的 `references/us设计.md` 模板内容
- 不实现任务执行的自动化（只做拆分，不做执行）
- 不改动 `agents/openai.yaml` 的接口定义

## Key Decisions

- 两阶段串行，中间有用户审批节点（支持多轮修改）：确保任务拆分基于最终确认的设计文档
- 任务分解为独立文件：与设计文档解耦，可独立分发和跟踪
- 综合拆分策略：不限定单一拆分维度，由 skill 根据设计文档整体内容判断
- 顺序标识代替图表：保持输出简洁，通过列表结构表达依赖
